## 1. 项目背景

### 1.1 什么是验证码

验证码（CAPTCHA）是一种"全自动公开图灵测试"，用来区分人类用户和计算机程序。常见的文字验证码是一张包含随机字符的图片，字符经过旋转、扭曲、添加噪点等干扰，人类能看懂但传统程序难以识别。

### 1.2 我们要做什么

输入一张验证码图片 → 输出图片中的文字字符串。

```
┌─────────────┐      ┌──────────────┐      ┌────────┐
│  验证码图片  │ ───→ │  识别模型     │ ───→ │ "A3B7" │
│  [图片文件]  │      │  (CRNN+CTC)  │      │  字符串 │
└─────────────┘      └──────────────┘      └────────┘
```

### 1.3 为什么不用现成的 OCR

通用 OCR 工具（如 Tesseract）是为识别自然场景中的规整文字设计的。验证码故意加入了扭曲、噪点、粘连等干扰，通用 OCR 在验证码上效果很差。我们需要**专门针对验证码训练的模型**。

## 3. 核心算法原理

### 3.1 为什么选择 CRNN 架构

验证码识别的本质是一个**图像到序列**的问题：输入是一张图片，输出是一个字符序列（字符串）。

传统的做法是先分割字符，再逐个识别。但验证码中字符经常粘连、重叠，分割很困难。

CRNN（Convolutional Recurrent Neural Network）的思路是：**不分割，端到端直接从图片预测字符序列**。

### 3.2 CRNN 的三个组件

```
输入图片 [B, 1, 60, 160]
     │
     ▼
┌─────────────────────────────────────────────────────┐
│  第一部分：CNN 卷积特征提取器                          │
│                                                      │
│  输入: 灰度图片 60×160                                │
│  作用: 提取图片中的视觉特征（边缘、形状、纹理）          │
│                                                      │
│  Conv+BN+ReLU+Pool  →  Conv+BN+ReLU+Pool  →  ...    │
│  [1, 60, 160]       →  [32, 30, 80]       →  ...    │
│  [32, 30, 80]       →  [64, 15, 40]       →  ...    │
│  [64, 15, 40]       →  [128, 7, 20]       →  ...    │
│  [128, 7, 20]       →  [256, 3, 10]       →  ...    │
│  [256, 3, 10]       →  [256, 1, 5]        ← 最终    │
│                                                      │
│  输出: [256, 1, 5] → 5个时间步，每个256维特征向量       │
└─────────────────────────────────────────────────────┘
     │
     ▼  (squeeze + permute: [256, 1, 5] → [5, B, 256])
┌─────────────────────────────────────────────────────┐
│  第二部分：BiLSTM 双向长短时记忆网络                    │
│                                                      │
│  输入: 5个时间步，每个256维特征                         │
│  作用: 理解字符之间的上下文关系                         │
│                                                      │
│  正向 LSTM:  → → → → →  (从左到右看)                  │
│  反向 LSTM:  ← ← ← ← ←  (从右到左看)                 │
│  拼接:       [正向隐藏态, 反向隐藏态] → 512维           │
│                                                      │
│  为什么用双向？                                       │
│  识别 "B" 时，不仅看当前位置的特征，                     │
│  还要看左边和右边的字符是什么，帮助消歧。               │
│                                                      │
│  输出: [5, B, 512]                                    │
└─────────────────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────────────────┐
│  第三部分：全连接分类层                                │
│                                                      │
│  输入: [5, B, 512]                                    │
│  作用: 把每个时间步的特征映射到字符概率分布              │
│                                                      │
│  Linear(512 → 37)  +  LogSoftmax                     │
│  37 = 36个字符(0-9, A-Z) + 1个blank                   │
│                                                      │
│  输出: [5, B, 37]  每个时间步在37个类别上的对数概率      │
└─────────────────────────────────────────────────────┘
```

**直觉理解**：

- **CNN** 像人的眼睛，负责"看"图片，把像素转化为特征
- **BiLSTM** 像人的大脑，负责"理解"，知道前后字符的关系
- **FC 层** 像人的嘴，负责"说出"每个位置是什么字符

### 3.3 CTC Loss — 解决对齐问题的关键

**核心问题**：模型输出的序列长度是固定的（5个时间步），但验证码的字符数量是变化的。而且我们不知道图片中第几个像素对应第几个字符。

**CTC（Connectionist Temporal Classification）的解决方案**：

1. 在字符集中加入一个特殊的 **blank** 标记（类似"这里没有字符"）
2. 模型在每个时间步输出所有字符+blank的概率
3. 解码时，合并连续重复字符，去掉 blank

**举例**：识别 "A3B7"

```
时间步:    t1    t2    t3    t4    t5    t6    t7    t8    t9    t10
模型输出:  A     A     blank  3     3     blank  B     B     7     7

CTC解码规则:
  1. 合并连续重复:  A A → A,  3 3 → 3,  B B → B,  7 7 → 7
  2. 去掉 blank:   blank → 删除

结果:  A  3  B  7  ✓
```

CTC 的妙处在于：**不需要知道字符在图片中的精确位置**，模型自己学习在哪里输出字符、在哪里输出 blank。

### 3.4 CTC 贪心解码（推理时使用）

```
每个时间步，选择概率最大的字符:
  t1: max(A=0.9, B=0.05, ...) → A
  t2: max(A=0.8, B=0.1, ...)  → A
  t3: max(blank=0.7, A=0.2)   → blank
  t4: max(3=0.95, 8=0.03)     → 3
  ...

然后: A, A, blank, 3, ... → 去重去blank → "A3..."
```

## 5. 模块详解

### 5.1 config.py — 配置中心

```python
# 字符集

```

### 5.2 dataset.py — 数据生成

#### 合成验证码生成流程

```
1. 随机生成4位文本 "A3B7"
2. 创建浅色背景图片 (160×60)
3. 逐字符渲染:
   - 随机字体大小 (30~44)
   - 随机位置（带抖动）
   - 随机旋转角度 (-20°~+20°)
   - 随机深色
4. 添加噪点（随机灰度像素点）
5. 添加干扰线（随机曲线）
6. 可选：高斯模糊
```

#### 字符编码

```
字符 → 索引:
  '0' → 1,  '1' → 2,  ...,  '9' → 10
  'A' → 11, 'B' → 12, ...,  'Z' → 36
  blank → 0

"A3B7" → [11, 4, 12, 8]
```

#### PyTorch Dataset

每次 `__getitem__` 实时生成新样本，等效于无限数据集——每个 epoch 看到的数据都不重复。


#### 维度变化全流程

```
输入:   [64, 1, 60, 160]   (64张图，灰度，60×160像素)
  ↓ CNN
特征:   [64, 256, 1, 5]    (64张图，256通道，1高×5宽)
  ↓ squeeze
压缩:   [64, 256, 5]       (去掉高度维度)
  ↓ permute
转置:   [5, 64, 256]       (5个时间步，64个样本，256维特征)
  ↓ BiLSTM
序列:   [5, 64, 512]       (双向拼接: 256×2=512)
  ↓ FC
输出:   [5, 64, 37]        (37个字符类别的对数概率)
```

#### 权重初始化

```python
Conv2d:    He 初始化 (Kaiming)  — 适合 ReLU 激活函数
Linear:    Xavier 初始化         — 适合 sigmoid/tanh 类型
LSTM:      正交初始化 (Orthogonal) — 稳定 RNN 训练
BatchNorm: 全1权重 + 全0偏置      — 标准做法
```

### 5.4 train.py — 训练流程

#### 训练循环伪代码

```
for epoch in 1..N:
    # ──── 训练阶段 ────
    model.train()
    for batch in train_loader:
        images, labels = batch

        # 1. 前向传播: 图片 → 模型 → 预测概率
        log_probs = model(images)              # [T, B, 37]

        # 2. 计算损失: 预测 vs 真实标签
        loss = CTCLoss(log_probs, labels)

        # 3. 反向传播: 计算梯度
        loss.backward()

        # 4. 梯度裁剪: 防止梯度爆炸
        clip_grad_norm(model.parameters(), max_norm=5.0)

        # 5. 更新参数: 沿梯度方向走一小步
        optimizer.step()

    # ──── 验证阶段 ────
    model.eval()
    val_loss, accuracy = evaluate_on_val_set()

    # ──── 学习率调度 ────
    scheduler.step()

    # ──── 早停检查 ────
    if no_improvement_for_N_epochs:
        break

    # ──── 保存检查点 ────
    if best_model:
        save_checkpoint()
```

#### 关键训练技巧

| 技巧 | 作用 | 配置 |
|------|------|------|
| **AdamW 优化器** | 自适应学习率 + 权重衰减 | `lr=1e-3, weight_decay=1e-5` |
| **Cosine 学习率调度** | 学习率先快后慢地衰减 | 从 1e-3 平滑降到 1e-6 |
| **梯度裁剪** | 防止梯度爆炸（RNN 常见问题） | `max_norm=5.0` |
| **早停** | 验证集不再提升时停止训练 | `patience=10` |
| **数据增强** | 每个 epoch 生成新数据，防止过拟合 | 在线生成 |
| **Batch Normalization** | 加速训练、稳定梯度 | 每个卷积层后加 BN |

#### 学习率调度（Cosine Annealing）

```
学习率
  ↑
  │╲
  │ ╲
  │  ╲
  │   ╲
  │    ╲
  │     ╲──────
  └─────────────→ epoch
  1e-3         1e-6
```

学习率从 1e-3 按余弦曲线平滑衰减到 1e-6。前期大步探索，后期小步精调。

## 6. 训练流程详解

### 6.1 训练过程中的数据流

```
一个 Batch 的完整流程:

1. DataLoader 取出一个 batch
   images: [64, 1, 60, 160]    64张灰度验证码
   labels: [256]               64个标签拼在一起 (每标签4字符)
   label_lengths: [64]         每个标签的长度

2. 前向传播
   images → CRNN → log_probs [T, 64, 37]

3. 计算 CTC Loss
   需要:
     - log_probs: [T, 64, 37]  模型输出
     - labels: [256]            真实标签（扁平化）
     - input_lengths: [64]      每个样本的输出时间步数 (都是T)
     - label_lengths: [64]      每个样本的标签长度 (都是4)

   CTC Loss 内部做了什么:
     a) 枚举所有可能的对齐路径（指数级数量）
     b) 用动态规划高效计算总概率
     c) 取负对数似然作为损失

4. 反向传播
   loss.backward()  →  自动计算每个参数的梯度

5. 参数更新
   optimizer.step()  →  参数沿梯度方向移动一小步
```

## 7. 推理流程

### 7.1 单张图片推理流程

```
输入图片
  ↓
load_image()          加载图片 (支持路径/bytes/PIL/numpy)
  ↓
preprocessor          预处理: 灰度化 → 归一化 → [-1,1] → Tensor [1,1,60,160]
  ↓
CRNN.forward()        前向传播 → [T, 1, 37] 对数概率
  ↓
argmax + decode       贪心解码: 每步取最大概率字符 → 去重去blank
  ↓
输出 "A3B7"
```

### 7.2 置信度计算

模型在每个时间步输出37个字符的概率分布。取最大概率值，对所有非 blank 的时间步求平均，得到整体置信度。

```
时间步:    t1     t2     t3     t4
最大概率:  0.99   0.98   0.95   0.99
(blank概率不计入)

置信度 = (0.99 + 0.98 + 0.95 + 0.99) / 4 = 97.8%
```

## 10. 局限性与改进方向

### 10.1 当前局限

| 问题 | 说明 |
|------|------|
| **训练数据是合成的** | 与真实验证码风格有差异，泛化能力有限 |
| **固定4字符长度** | 只能识别4位验证码 |
| **字符集固定** | 只认大写字母+数字，不含小写或特殊字符 |
| **没有使用注意力机制** | 对严重扭曲的字符处理能力有限 |

### 10.2 改进方向

| 方向 | 方法 |
|------|------|
| **用真实数据训练** | 收集标注真实的验证码数据集 |
| **更接近真实的数据生成** | 分析目标验证码风格，仿真生成训练数据 |
| **注意力机制** | 加入 Attention 帮助模型聚焦关键字符区域 |
| **变长支持** | 用 CTC 自然支持变长，或改用 Attention+Decoder |
| **更大的模型** | 更深的 CNN、更多 LSTM 层、更大的 hidden size |
| **数据增强增强** | 弹性形变、透视变换、颜色抖动等更强的增强 |
| **模型量化/蒸馏** | 部署时压缩模型，加速推理 |
